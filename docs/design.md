## 1. 画布与内容区

| 项 | 值 |
|---|---|
| 示例任务画布 | **8 × 20 cm**（1:10 缩放稿，实印 **80 × 200 cm**） |
| 内容区（示例模板） | x `0.74 → 7.30`、y `8.74 → 18.30` cm（6.56 × 9.56） |
| 可用高 `AVAIL_H` | 9.28 cm（去掉上下内边距） |
| 改动范围 | **只动「作品简介」区**；模板其余字段一字不动 |

> 评价字号务必**按 10× 折算**：幻灯片里的 4.20pt 实印约 42pt。
> 8×20cm 只是缩放稿，拿它的绝对尺寸去判断"字太小"是错的。

**内容区靠探测，不写死**（`template.detect_area`）：找模板自带的「作品简介」占位
文本框，按 `config.AREA_INSET` 向内收。判定规则是"顶部 ≈ `PH_TOP` 且宽 ≥ `PH_MIN_W`"，
所以**换模板不必改代码**；探测不到就退回 `FALLBACK_AREA`。
示例模板是 `tools/make_demo.py` 合成的，所以探测结果恰好等于 `FALLBACK_AREA` ——
这不是巧合，是模板按这套规则生成的。

## 2. 分块与网格

正文按 `## 小标题` 切成若干**分块**，网格决定每行放哪几块：

```yaml
grid:
  - [0]          # 通栏
  - [1]          # 通栏
  - [2, 3]       # 并排两块
```

**为什么要有版面节奏**：全篇一列到底太规整、并排到底又放不下宽幅图。
节奏有两种给法：**混排网格**（"第一行一块、第二行两块"的不规整），
或**全通栏图墙** —— 每行一条满宽图条，各行配图张数不同（2/3/3/0），
节奏由内容形态交替给出（示例就是这种，见下节）。
什么时候必须通栏，由**图条形态**决定（见 §4）：宽高比 > 3 的图条在半栏里会被压成细缝。

`row_fracs` 可以调行内各块的宽度比例，默认等分。

### 图主文辅：示例的真正结构（2026-10-15 晚，v2.6.0）

逐像素重量示例后确立的范式：**图占块高约 85%，文字是图条上方 1~2 行短说明**，
有的块甚至没有段落文字（只有小标题 + 图 + 短标签）。此前只从示例学了
"250~300 字"，却保留了"满幅正文段落 + 块底细缝图条"的旧结构 —— 字数达标、
范式没变，图仍然只有 0.76~0.81cm（实印 7.6~8.1cm）。

翻转范式的三个杠杆，按效果排序：

1. **砍块**：每块固定开销 ~0.44cm（胶囊标题 + 内边距），块数是图注之外
   最贵的刚性开销。无图的"背景"类段落并入相邻有图块作首段。
2. **砍到 1~2 行/块**：正文只做图的下饭菜，一条图注水平的短说明。
   本机任务 545 → 227 汉字后，三条图条全部通栏满宽。
3. **全通栏**：图条高 = 块内宽 / Σ(宽高比)，通栏满宽是图最大的唯一途径。
   并排块里的图天生小（半宽块的 Σ 一大图就矮）。

效果（本机任务）：图条 0.81 / 0.79 / 0.76 → **0.81 / 1.74 / 1.18 cm**
（结构条 +120%），8 张图全部上墙，字号 4.00pt 不降。
合规项 `C5` 同步改判"版面有节奏"（混排，或各行配图数不同）。

### 空间账（最硬的约束）

```
每多一个分块固定占 0.44cm（标题顶距 0.07 + 胶囊 ~0.28 + 间距 0.07 + 块底距 0.07）
→ 5 块就吃掉 2.2cm，剩下 ~7cm 装全部正文与配图
```

于是**块数与字号强互斥**：加一个小标题 ≈ 让正文字号掉 0.1pt 量级。
示例任务 4 块 / 545 字，字号才能顶到搜索上限 4.20pt；
同一套参数装 1200 字时字号会掉到 3.3pt 上下。想两全只能减字或减块。

## 3. 图条（一个分块多张图）

一个分块可以配 0~3 张图。多张时**等高横排**成一「图条」：高度统一，
宽度按各自 `w/h` 分配，总宽占满块内可用宽（不够就居中）。
**每张图各有一条自己的图注**，居中在该图正下方 —— 几条图共用一条注是被明令否掉的写法。

关键抽象是**单位高宽** `s = w/h`：

```
图条宽（不含张间间距） = 图高 × Σs       张间间距 = (张数-1) × FIG_GAP_IN
```

单图是 `Σs = w/h` 的特例，于是 `layout._cell` / `layout.solve` 里
**一套公式管 0/1/n 张图，不必分支** —— 这是让"支持单块多图"只动了很少代码的原因。

示例任务的 `#1` 块就是图条：4:1 的流程条 `s=4.0` + 1.5:1 的样品阵列 `s=1.5`，
`Σs = 5.5`，块内宽 6.06cm → 图高 `6.06 / 5.5 - 间距 ≈ 0.81cm`，
两张并排各占 3.24 / 1.22cm。

## 4. 排法分派规则（`layout.pick_mode`）

排法由**图条的实测形态**决定，不是全篇一个规则（判据 `w/h = 1/ratio = Σs`）：

| 图条形态 | 判据（w/h） | 排法 | 何时用 |
|---|---|---|---|
| 超宽条 | > 3.0 | **文上图下**（通栏横幅） | 流程条、时间轴这类长条 |
| 近方图 | ≤ 1.20 | **文左图右** | 单张近 1:1 的图 |
| 中间 | 1.2 ~ 3.0 | 通栏块文左图右 / 并排块文上图下 | 多数图表 |
| 无图 | — | **纯文本块**（正文占满块宽） | 该节本来就没有对应素材 |

任务文档里可以用 `<!-- mode: stack|side|text -->` 逐块写死，不写才走上面这张表。

判据用的是**裁白边之后**的尺寸（`imaging.trim_white`）—— 那才是真正上版的图。

### 三条踩出来的教训

1. **排法由图的长宽比决定，不能一刀切。**
   曾经把 4.36:1 的超宽流程条塞在正文右侧，压成 `3.20 × 0.59cm` 的一条细缝。
2. **半栏里做「文左图右」代价很大。**
   半栏块宽 3.07cm，切出图宽后正文列只剩 ~1.4cm（约 9 字/行）。
   示例任务的 `#2` 保留了这一形态，就是要**把这个代价摆在明面上**：
   它是可以用的（合规能过），但只有在图必须与文并排时才值得。
3. **纯文本块是正常形态，不是缺陷。**
   没有对应素材的小节就让它空着文字 —— 硬凑一张图才是错。

## 5. 求解器的取舍逻辑

两个未知量互相拉扯：**字号**与**配图尺寸**。

```
字号 ↑  → 行高 ↑            ┐
图   ↑  → 「文左图右」块     ├→ 总高 ↑ → 与 AVAIL_H 抢空间
          正文列变窄→行数 ↑  ┘
```

**搜索策略**（`layout.search`）：

1. 先扫「图高上限 → 该上限下能用的最大字号」，得到权衡表；
2. 在 **字号 ≥ `BODY_TARGET`（2.75pt）** 的前提下，取**最大的图高上限**
   —— 即"先保配图尺寸，再取字号"；
3. 行高定下后做**补白**：把行内多余高度补给该行的图条，消除块底大片空白。

当前示例任务的解：

| 项 | 值 |
|---|---|
| 正文字号 | 4.20 pt（顶到 `BODY_MAX`；实印 ≈42pt） |
| 行数 / 字数 | 28 行 / 545 字 |
| 图注字号 | 3.80 pt |
| 图高上限 | 2.20 cm（实际未触顶 —— 图高全被"块内宽"卡住） |
| 行高 | 1.20 + 2.50 + 3.97 = 7.87 ≤ 9.28 cm |
| 形状数 | 31 |

逐块（`#r 排法 块宽/正文宽 → 行数 + 图条 → 块高`）：

```
#0 text   6.26 / 6.06 →  3 行 0.71cm                无图          块高 1.20
#1 stack  6.26 / 6.06 →  4 行 0.95cm   图条 2x 6.06 × 0.81      块高 2.50
#2 side   3.07 / 1.41 → 13 行 3.08cm   图条 1x 1.33 × 1.25      块高 3.97
#3 stack  3.07 / 2.87 →  8 行 1.90cm   图条 1x 2.87 × 1.33      块高 3.97
```

> 还剩 1.41cm 纵向余量（7.87 vs 9.28）。求解器把余量优先给配图而不是字号，
> 所以示例看起来"还有空" —— 这是设计选择，不是没排满。

### 字数预算：先定字数，再谈版式

**正文字数是这张海报里唯一的"自变量"。** 其余量都是它的因变量：

```
字数 ↑ → 需要的行数 ↑ → 总高 ↑ → 要么压字号、要么压图、要么溢出
```

所以求解器真正的天花板不是 `BODY_MAX`，而是**你写进去多少字**。同一份版式预算下：

| 正文字数 | 配图 | 求解出的字号 | 结果 |
|---|---|---|---|
| 752 汉字 | 5 张 | 3.30 pt（实印 33pt） | 每块都排到 5~9 行，密不透风 |
| 545 汉字 | 5 张 | 3.85 pt（实印 38.5pt） | 同样 5 块，字号大 17%、少 2 行 |
| 545 汉字 | **7 张** | **4.00 pt（实印 40pt）** | 补进来的图让图条变矮，字号再涨 4% |

注意第三行：**图变多了，字反而更大了** —— 因为图条矮了，纵向空间腾出来了。
"加字"和"加图"对字号的作用方向相反，这是本节与下一节要分开讲的原因。

这个"字越多、字号越小"的机制是**自我抵消**的：把脚注级别的细节写进正文，
换来的不是"信息更多"，而是**所有字都变小、谁也看不清**。海报是站着远看、看图为主的媒介，
不是可以凑近读的小字报。

于是有了合规项 **E6**：单块 ≤ `TEXT_CHAR_BLOCK_MAX`（**220**）汉字、全篇 ≤
`TEXT_CHAR_TOTAL_MAX`（**800**）汉字（计数只算汉字，数字 / 英文 / 标点不计）。

**上限最初是从样张量出来的**：参考样张全篇约 250~300 汉字，最重的文本块约 130 字，
其余板块基本只有图 + 短标签 —— 图文比约 3:1。拿它的量级当订单块与全篇的天花板，
我们自己留一点余量（当时的取值是 120 / 550）。

后来按一份需要把机制讲清楚的文案**放宽过一次**（120/550 → 220/800）：原阈值是按
样张的图文比一刀切，会把"讲清楚"的详版文案误判成小字报；而放宽后求解出的字号
（3.30pt，实印 33pt）仍远高于 `BODY_MIN`（2.60pt）的下限。
**放宽的正当性只来自"字号还够大"，不来自"字写多了"** —— 阈值上调不等于别处可以随便塞。
超限时的动作顺序是**先删、后调**：删铺垫、删常识、删同义复述；
实在该讲的，再谈调阈值或减块。

删的时候**删什么**：删铺垫、删常识、删"随着…的快速发展"这种开场、删同义复述。
**不删**关键数据（数值 / 单位 / 条件）、专有名词、结论。E6 卡的是字数，不是信息量。

### 配图预算：窄列里能放几张图，是几何算出来的

字数的问题有 E6 兜着；配图的问题此前没有明确说法，踩过一次才发现
**它有更硬的上限**。素材源文档里的内嵌图未必都能上墙 —— 上几张不是"想不想"，
是**窄列块的宽度除以 Σ(w/h) 算出来的**：

```
图高 = (块内可用宽 − (张数−1) × FIG_GAP_IN) / Σ(w/h)
```

并排窄列块约 3.1cm 宽，放 3 张图时 Σ(w/h) 普遍涨到 5 以上，
图高掉到 **0.54cm（实印 5.4cm）**，直接撞合规 `B6` 的可读下限 0.70cm（实印 7cm）。
所以：**窄列块最多 2 张，超宽通栏块最多 3 张**（`spec.MAX_FIGURES`），
而 `[[0],[1],[2,3],[4]]` 这种 4 行网格的配图上限就是 2 + 3 + 2 = 7 张。

这里有个反直觉的耦合，值得单独记住：

- **加一张图可能让字变大** —— 图条变矮 → 腾出纵向空间 → 求解器敢放大字号；
- **加一张图也可能让版式报废** —— 每张图都有自己的可读下限，塞成细缝比字小更直接地
  让图失去意义。

所以顺序是：**先按公式算窄列能放几张 → 再决定哪几张上墙 → 最后才让求解器调字号**。
别指望求解器兜底，它只能保证"不溢出"，保证不了"看得清"。

补图时优先补**支撑关键数据的那张**：正文里写了什么数，就该有对应那张图的坐标轴。
数值没有图支撑、或图没有正文认领，都属于图文错配（合规 `D1` / `D6` 守着）。

### 横向放大的唯一途径

图条高度受**块内宽 / Σs** 卡脖子（不是受 `IH_MAX` 卡）：想放大图片只有

1. 减少正文字数（见上一节，这是最有效的一条）；
2. 减少图条里的张数（每少一张，剩下的那张就宽一截）；
3. 换更宽的素材（把方图裁成宽幅）。

## 6. 视觉语言

照样张的视觉语言实现（`writer.py` + `preview.py` 两侧保持一致）：

- **虚线圆角框**：`#7FB5D9` / 0.8pt / `prstDash=dash` / 圆角 0.14cm
  （`roundRect` 的 `adj` 是 `RADIUS / min(w,h)`）；
- **渐变块底**：白 → `#E8F4FD` 竖向渐变。**绕开 python-pptx 的 `gradient_angle`**，
  直接写 `a:lin/@ang = 5400000`（= 90°，自上而下）；
- **胶囊小标题骑在整条虚线上**：虚线先加、胶囊后加（z 序），虚线从胶囊背后穿出；
- 配图加 0.5pt 淡边 `#BFD8EA` —— 白底图贴白底会找不到边界；
- 图注居中在图正下方、宽度 = 图宽（所以窄图的注必须写得短）。

## 7. 渲染器一致性

**模型自洽 ≠ 渲染器认账。** 这一节是这块版面里最贵的一课：

`a:spcPts`（绝对点值行距）会被 PowerPoint **四舍五入到整点** ——
写 `552`（5.52pt）实际按 **6.0pt** 排，一行高 8.7%，九行变十行，
**末行就钻进配图底下**。所以行距一律写 `a:spcPct`，
在 pptx 里也开 `bodyPr/@hangingPunct="1"` 让断行策略与预览一致，
并且求解时取**三种**标点策略里最悲观的行数（`push` / `hang` / `pull`）。

完整的量化表、量测手法（用 `<a:br/>` 消掉行框高）与四层守卫见
[`rendering-notes.md`](rendering-notes.md)。

## 8. 被排除的方案（别再试）

- **"满幅正文段落 + 块底细缝图条"**（2026-10-15 已被推翻）：文字块占大头、
  图压成 0.76~0.81cm 细缝，是"字多图小"的根源。正确范式见 §2「图主文辅」。
- **左右两栏（左边全是文字、右边全是图片）**：样张是**每个虚线框里**
  同时装该节的文字与配图，不是按"列"分。
- **全篇同一个排法**：见 §4 教训 1。
- **图按"叙事顺序"全局编号**：图必须落在支撑它那段正文的块里，
  否则评审一眼就能看出图文不对位（现在有几何测试守着）。
- **把借来的图填进没素材的块**：宁可留纯文本块。
- **通用通栏横幅图**：把一行图都改成"铺满块宽的横幅"会多花 1cm 以上高度，
  必须把同行的图压到 0.75cm 以下才装得下 —— 不划算。
