# 合规要求清单

> **这份清单是"合格的墙报长什么样"的唯一出处。**
> 代码里的对应实现在 [`src/poster/compliance.py`](../src/poster/compliance.py)（`REQUIREMENTS`），
> 构建后跑一遍：

```bash
python build.py --check      # 构建 + 自检，报告写到 dist/compliance-<任务id>.md
python build.py --check -q   # 只打印未通过的项
```

退出码：硬性项全部通过为 `0`，有硬性未通过为 `2` —— 可以直接串进脚本 / CI。

## 为什么要有它

要求散在四个地方：**模板本身**（只做「作品简介」区、画布 8×20cm）、
**样张**（虚线圆角框、胶囊标题骑线、图文同框、混合网格、一图一注）、
**评审通知**（图文必须对位）、**历次返工的血债**（字体缺字形、被压成细缝的图、构建不可复现）。

靠人记忆一定会漏。本仓库漏过两次，两次都不是能力问题：

| 事故 | 后果 | 现在由谁拦 |
|---|---|---|
| 一张表征图被挂到了**不是讨论它**的那个块下 | 图文不对位，被评审点名返工 | **D1**（几何包含关系断言） |
| 两张图共用一条图注 | 用户打回"一张图一个图注" | **D2 / D5**（图数与图注数逐张配对） |

所以每条要求都编了号、都尽量写成**可执行的断言**；实在判不了的（例如"这张图在讲什么、该配哪段正文"）
标为**人工**，并把**判读依据**写死在条目里，避免下次又认反。

## 硬性项（hard，不通过就是不合格）

| 编号 | 要求 | 出处 | 违反时改哪里 |
|---|---|---|---|
| A1 | 只动「作品简介」区，模板既有字段一字未改（`number:` 覆写的编号框除外） | 模板 | `template.py::is_placeholder` 的判定；别去清占位框以外的文本。任务文档写了 `number:` 时，`writer.set_number` 会**主动**覆写「作品编号」框，该框从"原样保留"的比对里剔除 |
| A2 | 模板背景图保留，产物配图数 = 文档声明数 | 模板 | 别删模板自带图片；`figures:` 指令 |
| B1 | 画布不被改动（8×20cm 缩放稿 = 实印 80×200cm） | 模板 | `writer.py` 不要改 slide size |
| B2 | 正文字号不低于 `config.BODY_MIN`（实印后仍可读） | 评审 | 减字数 / 减块数 / 调 `style:` 里的搜索区间 |
| B3 | 内容总高不溢出内容区（`lay.total ≤ AVAIL_H`） | 模板 | 同上；或减一个小节 |
| B4 | 每个分块都落在「作品简介」内容区内 | 模板 | 检查 `area:` / `AREA_INSET` / 网格是否过密 |
| B5 | 正文列宽 ≥ `config.TW_MIN`（1.30cm），不出现细长条 | 样张 | 该块改 `mode: stack`（别用 side），或调 `row_fracs` |
| B6 | 图高 ≥ `config.IH_MIN_READABLE`（0.70cm，实印 7cm），不出现细缝 | 评审 | 超宽图别塞半栏（历史事故：5.46:1 的流程条被压成 0.46cm）；改通栏或换图 |

## 版式项（照样张）

| 编号 | 要求 | 出处 | 违反时改哪里 |
|---|---|---|---|
| C1 | 每个分块是**虚线圆角框**（`prstDash=dash`） | 样张 | `writer.rrect` / `config.RADIUS` |
| C2 | 块底为白 → 浅蓝**渐变**（`BLOCK_C1 → BLOCK_C2`） | 样张 | `writer._grad` / `config.BLOCK_C1/C2` |
| C3 | 小标题是**蓝色胶囊**（全圆角 + 渐变 + 白字粗体） | 样张 | `writer.chip` / `config.CHIP_C1/C2` |
| C4 | 胶囊**骑在一条整宽虚线上**（虚线先画、胶囊后画） | 样张 | `writer.dashed_link` 的 y 与 z 序 |
| C5 | **版面有节奏**：混排网格（既有通栏行也有并排行），或全通栏图墙但各行配图数不同 —— 不是千行一面 | 样张 | 任务文档 front-matter 的 `grid:` 与各行 `figure:` |
| C6 | **图文同框**：有图的分块内同时有正文（不是"左栏全文字、右栏全图片"） | 样张 | `grid:` 与 `mode:` |
| C7 | 正文与配图不相互重叠 | 工程 | 求解器 `_cell` 的宽高分配 |
| C8 | **文字实际需要的高度 ≤ 自己声明的框高**（按最悲观断行重算） | 工程 | 算少了行数 → 渲染器把多出来的那行画到框外、被下面的图盖住（2026-10-14 事故）。改 `MEASURE_SAFETY` / 断行策略 / 减字 |
| C9 | **行距一律写 `spcPct`**，不许 `spcPts` | 工程 | PowerPoint 会把绝对点值行距**四舍五入到整点**（5.52pt → 6.0pt，一行多 8.7%），是上面那次事故的根因。见 `writer._set_line_spacing` |
| C10 | `bodyPr` 的自动调整子元素**至多一个**（`noAutofit` / `normAutofit` / `spAutoFit` 三选一） | 工程 | 两个并存会让 PowerPoint 判定**整份文件损坏、拒绝打开**。见 `writer._force_no_autofit` |
| C11 | 悬挂标点开关与断行策略一致（`HANG_PUNCT` ↔ `bodyPr/@hangingPunct`） | 工程 | 不一致会让行首冒出「，。、」，或让模型与渲染器的断行不一致 |
| C12 | 正文**不用两端对齐**（`algn="just"`） | 工程 | 两端对齐把每行余宽摊到字间，**中文也被撑开** —— 「升至」看起来成了「升 至」，读者会以为文案里插了空格。左对齐只把余宽留在行尾，中文字距恒定。见 `writer.add_text`（默认 `PP_ALIGN.LEFT`）与 `preview`（预览同口径，不再模拟拉伸） |

## 渲染器一致性（这一组是 C7 的补丁）

C7 只看**声明的框**有没有和图标几何打架。可如果引擎把文字需要的高度**算少了**
（少算一行），声明框自己看着没问题，渲染器却会把多出来的那行画到框外 ——
2026-10-14 的版面事故正是如此：`spcPts 552` 被 PowerPoint 按 6.0pt 排，
某个块实际排了 10 行而引擎只算了 9 行，第 10 行整行钻进它下面那张图里。

C8~C11 把「渲染器会怎么排」重新算一遍，与写进 pptx 的值对账；F5 再让真渲染器
亲自复核一遍。三个层次的守卫缺一不可：

| 层次 | 守的是 | 编号 |
|---|---|---|
| 几何 | 声明的框之间不打架 | C7 |
| 模型对账 | 渲染器的行距 / 断行口径重算后仍放得下 | C8 / C9 |
| 文件合法 | 产物能被 PowerPoint 打开 | C10 |
| 真渲染器 | PowerPoint 自己报的墨迹框不压图 | F5 |

阈值与开关见 `config.py`：`LINE_FACTOR`（行距倍数）、`LINE_REF_FACTOR`（单倍行距 = 字号 × 1.20）、
`MEASURE_SAFETY`（量算宽度折扣）、`HANG_PUNCT`（悬挂标点）。

## 图文对位项（评审红线）

| 编号 | 要求 | 出处 | 违反时改哪里 |
|---|---|---|---|
| D1 | 每张图都落在**声明它的那个分块**内 | 评审 | 任务文档里该小节的 `<!-- figure: ... -->` |
| D2 | **一张图一条图注**，不得几图共用一注 | 评审 | `<!-- figure: 图a | 图1 xx ; 图b | 图2 yy -->` |
| D3 | 图注在该图**正下方**且水平**居中于该图** | 样张 | `writer.place_figs` 的图注 x/宽 |
| D4 | 图注宽度不超过所注图宽（不压到邻图） | 工程 | 图注文字太长就缩短（窄图的注会折行） |
| D5 | 图号从 **图1** 起连续、不重不漏 | 样张 | 图注里的编号 |
| D6 | **素材归属按坐标轴判读**并人工复核 | 评审 | 见文末「人工项判读依据」 |

## 文字项

| 编号 | 要求 | 出处 | 违反时改哪里 |
|---|---|---|---|
| E1 | 无**字体缺失字形**（`℃ ₂ ⁺ ⁻ ³` 等），一律 ASCII 等价写法：`°C` / `at%` / `Fe3+`（写进 `^{}` 角标） | 工程 | 任务文档正文（微软雅黑缺这些字形，上版是豆腐块）。**化学式/单位不许用 Unicode 上下标字符**，要用 `E7` 的角标标记 |
| E2 | 每个分块都有正文，且无占位 / 未完成痕迹（TODO、待补、`（无配图）`…） | 评审 | 任务文档正文 |
| E3 | 小标题互不重复 | 工程 | 任务文档的 `## 小标题` |
| E4 | 标红只用于**关键数据**（占比 ≤ 40%）— 提示项，超了不拦 | 样张 | 任务文档里 `**强调**` 的数量 |
| E5 | 每条图注都非空 | 工程 | `figure:` 指令的图注 |
| E6 | **正文字数有上限**：单块 ≤ `config.TEXT_CHAR_BLOCK_MAX`（220）汉字、全篇 ≤ `TEXT_CHAR_TOTAL_MAX`（800）汉字 | 样张 | 上限最初按参考样张的图文比定（120 / 550），**2026-10-16 按一份需要把机制讲清楚的详版文案放宽过一次**（原阈值会把"讲清楚"误判成小字报）。字越多 → 字号被压得越小 → 上了墙谁也看不清；**放宽的正当性只来自"求解出的字号仍远高于 B2 的下限"，不来自"字写多了"**。超限时的动作顺序是**先删、后调**：删铺垫句（背景、意义、常识性解释），**关键数据与结论一个都不能少** |
| E7 | **化学式 / 单位用真角标**：`Fe^{3+}`（上标）、`I_{D}/I_{G}`、`元/m^{2}`（下标） | 工程 | 直接写 `Fe3+` / `m2` / `ID/IG` 会把电荷数排成与字母同高，属排版错误。角标只位移、不缩放，**不改变行宽**，故不影响断行估算 |

## 交付项

| 编号 | 要求 | 出处 | 违反时改哪里 |
|---|---|---|---|
| F1 | 产物名与任务文档 `output:` 一致且存在 | 工程 | front-matter `output:` |
| F2 | 产物可被重新打开（zip / xml 合法） | 工程 | `writer.save` / 模板是否损坏 |
| F3 | 构建**可复现**（同输入同字节） | 工程 | `repro.freeze_zip`（否则每次构建往 git 里塞 16MB） |
| F4 | 预览图已生成（`preview_intro.png` / `preview_full.png`）— 提示项 | 工程 | 别用 `--no-preview` 出最终稿 |
| F5 | **PowerPoint 实排复核**：无文字压图、无文字溢出声明框 | 工程 | 前面 C1~C11 都是"按模型自洽"；只有这条能让渲染器亲自说话。本机没装 PowerPoint 时记为跳过（不算不合格）。也可手跑 `python tools/ppt_verify.py` |

## 流程项（人工）

| 编号 | 要求 | 出处 | 怎么做 |
|---|---|---|---|
| G1 | 每次改动后跑 `python build.py --check`，硬性项全绿再提交 | 工程 | 改文案 / 换图 / 调版式之后 |
| G2 | 版式变更记入 `CHANGELOG.md`（含动因与教训） | 工程 | 写**动因与教训**，不只记结果 |

## 人工项判读依据

这三条判不了（或不该由脚本判），报告里会列出来等你确认：

| 编号 | 要求 | 判读依据 |
|---|---|---|
| D6 | 素材归属 | **看坐标轴，不看图名**：轴标签说明这张图是什么表征或数据（谱图 / 性能曲线 / 显微或实物照 / 流程示意），据此确认它是否落在**讨论它的那个分块**里。曾经认反过，务必看图。 |
| G1 | 每次改动后自检 | 改完文案 / 图 / 版式，重跑 `python build.py --check`，硬性项全绿再提交。 |
| G2 | 变更留痕 | 版式 / 引擎变更在 `CHANGELOG.md` 对应版本条目下写清**动因与教训**，不只记结果。 |

## 维护约定（重要）

1. **加一条要求** → 先在 `src/poster/compliance.py::REQUIREMENTS` 里加 `Item`（写好编号 / 出处 / 检查函数），
   再在本文件表格里补同一编号的一行。
2. 两边不一致会**直接测试失败**（`tests/test_compliance.py::test_doc_lists_match_code`）——
   加了检查不写文档、或写了文档不实现，都过不了。
3. 硬性项必须全绿；提示项允许亮，但要在提交信息里说一句。
4. 阈值能放到 `config.py` 的（`BODY_MIN` / `TW_MIN` / `IH_MIN_READABLE` / `RADIUS`…）就放过去，
   任务文档可以用 `style:` 段覆盖，换赛事时不必改代码。
