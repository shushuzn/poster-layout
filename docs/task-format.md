# 任务文档格式

**一个墙报 = 一份任务文档。** 引擎不认识任何具体赛事，它只认这份文档。

```
tasks/<任务id>/
├── task.md        ← 任务文档：排版设置 + 全部图文内容
└── assets/        ← 该任务的配图
```

新建：

```bash
python build.py --new my-poster      # 从 tasks/_template.md 复制一份
```

构建：

```bash
python build.py my-poster            # 或 python build.py tasks/my-poster/task.md
python build.py                      # tasks/ 下只有一个任务时可以省略
python build.py --list               # 列出全部任务
```

---

## 一、任务文档长什么样

```markdown
---
id: demo
title: 示例任务 · 通用墙报排版引擎
template: "assets/template.pptx"
output: demo-poster.pptx
dist: ../../dist
figures_dir: assets
area: auto
grid:
  - [0]
  - [1]
  - [2, 3]
---

## 示例说明
没有支撑这段正文的图，就不配图。

## 素材与方法
<!-- figure: fig_flow.png | 图1  工艺流程 ; fig_sample.png | 图2  样品阵列 -->
正文……关键数据用 **两个星号** 包起来就标红。

## 表征与讨论
<!-- figure: fig_map.png | 图3  二维分布 -->
正文……
```

（这份内容就是 [`tasks/demo/task.md`](../tasks/demo/task.md) 的骨架，
可以直接拿它当起点：复制整个目录、改名、换素材、改文案。）

两半各管一件事：

| 位置 | 管什么 |
|---|---|
| `---` 之间（YAML front-matter） | **任务级设置**：模板、产物名、内容区、网格、风格覆盖 |
| 正文的每个 `## 小标题` | **一个分块**：小标题 + 该块正文 + 该块配图 |

**小节的顺序 = 展示顺序**，`## 标题` 就是版面上那个胶囊里的字。

---

## 二、front-matter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 否 | 任务标识；默认取目录名 |
| `title` | 否 | 只用于日志与 `--list` |
| `template` | 是* | 模板 pptx 路径（相对本文档）。*不写则用 `assets/template/` 下唯一的 pptx，或 `POSTER_TEMPLATE` |
| `output` | 否 | 产物文件名，默认 `poster.pptx`；缺 `.pptx` 会自动补 |
| `number` | 否 | 作品编号。填了就按 `作品编号：<值>` 覆写模板里的编号框（沿用原框字号与颜色）；**不填则模板一字不动** |
| `dist` | 否 | 产物目录，默认仓库 `dist/`；可被 `POSTER_DIST` 覆盖 |
| `figures_dir` | 否 | 配图目录，默认本文档同级的 `assets/` |
| `area` | 否 | 可排版内容区。`auto`（默认）＝由模板占位框推导；或写 `[x0, y0, x1, y1]`（cm）钉死 |
| `grid` | 否 | 每行放哪些小节，默认「首节通栏 + 其余两两并排」 |
| `row_fracs` | 否 | 行内列宽比例，默认等分 |
| `style` | 否 | 版式覆盖，键名见 `src/poster/config.py` 的 `OVERRIDABLE` |

### `area: auto` 是怎么推出来的

模板自带一个「作品简介」占位文本框（残留旧文字的、会被清空的那个）。引擎找到它，
按实测内缩量 `AREA_INSET = (左 0.05, 上 0.22, 右 0, 下 0.42)` 收一圈，就是真正能排版的矩形。
坐标先吸附到 0.01cm（模板里的形状坐标带亚 0.01cm 噪声）。

探测不到占位框就退回 `config.FALLBACK_AREA`，并打一条警告。**换了赛事模板后，
务必看一眼构建日志里的内容区是否合理**；不合理就在文档里写死 `area:`。

### `grid` 与 `row_fracs`

`grid` 是"第几行放哪几节"：

```yaml
grid:
  - [0]            # 第 1 行：第 0 节独占通栏
  - [1, 2]         # 第 2 行：第 1、2 节并排
  - [3, 4]
```

要求**不重不漏**地覆盖全部小节，否则报错。省略则自动生成：

| 小节数 | 默认网格 |
|---|---|
| 1 | `[[0]]` |
| 2 | `[[0], [1]]` |
| 5 | `[[0], [1, 2], [3, 4]]` |
| 6 | `[[0], [1, 2], [3, 4], [5]]` |

`row_fracs` 给行内列宽比例，每一行必须和为 1：

```yaml
row_fracs:
  - [1.0]
  - [0.6, 0.4]
```

## 三、小节内的指令

指令写成 HTML 注释，独立一行，放在该小节任意位置（习惯放在标题下面）：

| 指令 | 作用 |
|---|---|
| `<!-- figure: 文件名 \| 图注 -->` | 给本块配**一张**图。文件名相对 `figures_dir`；`\|` 后面是图注 |
| `<!-- figure: 文件a \| 图1 甲 ; 文件b \| 图2 乙 -->` | 给本块配**多张**图（**分号**分隔，最多 3 张），版面上**等高并排成一「图条」**；**一张图写一条图注**，逐张居中在各自图的下方 |
| `<!-- figure: 图a \| 图1 甲 ; 图b \| 图2 乙 \|\| 图c \| 图3 丙 -->` | **图网格**：双竖线 `\|\|` 分「图条行」，行内仍用分号分张；行与行上下叠排（每行最多 3 张、一块最多 3 行）。这是**分栏版式下把图放大**的唯一手段 —— 半栏块放不下的一行三图，拆成两行后每张可到 1.2~2.2cm |
| `<!-- figure: none -->` | 本块不配图（纯文本块，正文占满块宽） |
| `<!-- caption: 图1 甲 ; 图2 乙 -->` | 单独指定图注（分号分隔，条数须与图数一致） |
| `<!-- mode: auto\|stack\|side\|text -->` | 强制本块的图文排法（图网格一律走 stack） |

**一张图一条图注，不许几图共用一注**（这是合规硬性项 D2）：
- 多图必须逐张写注，少写一条会**直接报错**并指出是哪张图缺注；
- 用**逗号**列多个文件名也会报错（那是"几图共用一注"的旧写法），会提示改用分号。

**每条指令在同一小节里只能写一次**，写两次会报错 —— 否则后一行会静默顶掉前一行。

### 图条：多张图怎么摆

同一个块里的多张图**等高横排**：高度统一，宽按各自长宽比分配，总宽占满块内可用宽
（不够就居中）。这比"每张图各占一行"省高度得多，也是示例墙报的做法。

图条的形态（等价长宽比 `总宽 / 图高 = Σ(每图 w/h)`）决定它自己的排法：

| 图条形态 | 判据（w/h） | 排法 |
|---|---|---|
| 超宽条 | > 3.0 | 文上图下（通栏横幅） |
| 方形 | ≤ 1.20 | 文左图右 |
| 其余 | 1.2 ~ 3.0 | 通栏块文左图右 / 并排块文上图下 |

一张图只是「图条里只有一张」的特例，规则完全一致。张与张之间的间距是
`style: FIG_GAP_IN`（默认 0.10cm）。

**图注逐张写**：每条图注居中在自己那张图的正下方，宽度就是该图的宽度 —— 所以窄图的
图注会折行，图注要写得短些（太长会顶高整行）。

`mode` 取值：

| 值 | 含义 |
|---|---|
| `auto`（默认） | 由图条的长宽比自动决定：超宽条→文上图下；方形→文左图右；其余按块宽定 |
| `stack` | 文上图下（图条居中铺在正文下方） |
| `side` | 文左图右 |
| `text` | 只要文字，不要图 |

没配图的块只能是 `text`（不写就自动落到 `text`）；写了 `side`/`stack` 会报错。

**指令名写错会直接报错**，不会被静默忽略 —— 免得图没上去还以为是版式问题。

## 四、正文的写法

- **每段一行**（编辑器里自动换行即可）。**段落内的换行会被忽略**，所以不要靠换行断句。
- **空行分段**。一个块可以有多段。
- `**要标红的字**` → 用 `config.RED`（默认 `#C00000`）渲染。
- `^{上标}` / `_{下标}` → **真角标**（化学式与单位必须用它）：`Fe^{3+}`、`I_{D}/I_{G}`、
  `12.34 元/m^{2}`。角标只把字形整体位移、**不缩放字号**，所以行宽与断行结果
  跟不写角标时完全一样；渲染成 PPT 时写的是 `a:rPr/@baseline`（`config.SCRIPT_BASELINE`）。
  想输出字面量 `^{`，写成 `\^{`。
- `<!-- ... -->` 注释会整段丢掉（可以跨行），放心写给自己看的备注。
- 想改标红色，在 `style:` 里覆盖 `RED`。

> ⚠️ 模板用的「微软雅黑」缺 `℃` `ₓ` `⁺` `³` 等字形，写进去会显示成方框。
> 请用 ASCII 等价写法：`°C`、`at%`；**化学式与单位不要用 Unicode 上下标字符**
> （`Fe³⁺`、`m²` 都是错的），一律写成 `Fe^{3+}`、`m^{2}` 走角标。
> 测试会拦住缺失字形（`E1`）与 ASCII 直写的化学式（`E7`）。

## 五、`style` 覆盖

只列常用几项，全量见 `config.OVERRIDABLE`：

| 键 | 默认 | 说明 |
|---|---|---|
| `RADIUS` | 0.14 | 块圆角半径（cm） |
| `BORDER_W` | 0.8 | 块虚线框线宽（pt） |
| `TITLE_SZ` | 5.0 | 胶囊小标题字号（pt） |
| `CHIP_C1` / `CHIP_C2` | 蓝 | 胶囊渐变两端 |
| `BLOCK_LINE` | `#7FB5D9` | 虚线框颜色 |
| `BLOCK_C1` / `BLOCK_C2` | 白→`#E8F4FD` | 块底渐变 |
| `FIG_GAP_IN` | 0.10 | 同一图条内两图的间距（cm） |
| `RED` | `#C00000` | 标红色 |
| `BODY_MAX` / `BODY_MIN` | 4.20 / 2.60 | 正文字号搜索区间（pt） |
| `BODY_TARGET` | 2.75 | 字号目标线，见 `design.md` |
| `FONT_FAMILY` | 微软雅黑 | 字体名（PPTX 里写死这个名字） |

颜色写 `[R, G, B]`（0-255，可写十六进制）：

```yaml
style:
  CHIP_C1: [0x1F, 0x7F, 0xC0]
  RADIUS: 0.2
```

写错的键名会报错并列出可用键 —— 不会静默失效。

> 覆盖是**进程内全局**的：一个进程只构建一个任务。这正是 CLI 的用法。

## 六、写完先自检

```bash
python build.py --check      # 或 make check
```

构建完会逐条对照 [`compliance.md`](compliance.md) 的合规清单（共 40 项：硬性 35 / 提示 2 /
人工 3），报告写到 `dist/compliance-<任务id>.md`；硬性项全绿退出码为 0，否则 2。

跟本文件关系最大的几条：**D2** 一张图一条图注、**D1** 图必须落在声明它的块内、
**E6** 正文字数有上限（单块 220 / 全篇 800 汉字，`style:` 可覆盖）、
**D5** 图号连续、**E1** 无缺失字形、**E7** 化学式与单位用 `^{}`/`_{}` 角标、**B6** 图不会被压成细缝。
写任务文档时对着这几条看一遍，比出稿后被评审打回便宜得多。

> **F5** 会用 PowerPoint 实排复核（无文字压图 / 无溢出）；本机没装 PowerPoint 时该项显示为
> **跳过**，其余项照常判。
