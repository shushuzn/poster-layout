# 墙报排版引擎（poster-layout）

**一份墙报 = 一份任务文档。** 引擎不认识任何具体赛事 —— 换比赛、换模板，
只写一份新的 `tasks/<id>/task.md`，**不动代码**。

## 什么时候用它

- 用户要出一份**学术墙报 / 海报**（赛事的「作品简介」区），手上有文案 + 配图 + 一张官方模板 pptx
- 用户要**改**一份已有墙报：换文案、换图、调网格/配色、加作品编号
- 用户要核对一份墙报**是否合格**（版式、图文对位、文字压图）

不适用：从零设计一张非模板驱动的海报（那用别的工具）；模板结构差异极大、
且用户不接受「只做作品简介区」的约束时，先跟用户对齐。

## 不变式（动手前先读，违反会被合规项或测试拦下）

1. **只做「作品简介」区。** 模板上的**作品名称 / 项目成员 / 本科生组 / 作品编号**
   一字不动 —— 唯一例外是任务文档写了 `number:`，此时由引擎覆写编号框。
   （合规 `A1`，`tests/test_layout.py` 守护）
2. **画布是 1:10 缩放稿**（8×20cm 稿 = 实印 80×200cm）。稿面上所有 pt 值 ×10 才是实印效果；
   评价字号能不能看清，按实印算。
3. **正文字数是第一自变量**：字数 ↑ → 字号被压小。硬上限 **单块 220 / 全篇 800 汉字**
   （`E6`，只数汉字）。**超限时删铺垫句，不许放宽阈值糊过去**。
4. **图只配在支撑它的那一块**（`D1`，几何包含关系断言）。认图看坐标轴/轴标签，别凭文件名猜。
5. **一张图一条图注**，多图用 `;` 分隔、逐条写注（`D2`）。多图用逗号分隔会直接报错。
6. 行距只写 `spcPct`、正文不用两端对齐、自动调整子元素至多一个 —— 这些是渲染器一致性
   要求（`C9`~`C12`），由 `writer.py` 保证，**别绕开它手改 XML**。
7. **合规清单是唯一出处**：`docs/compliance.md` 与 `src/poster/compliance.py::REQUIREMENTS`
   双写，不一致会测试失败。出稿必跑 `--check`，硬性项全绿才准交付，**不得绕过清单交半成品**。

## 文案书写规范（本仓库的用户偏好，非引擎强制）

写中文墙报文案时按这套来，用户会检查：

- **标点一律半角**：圆括号 `()`、顿号与逗号统一写 `,`；句末与停顿类 `。：；—` 仍留全角。
- **不留多余空格**：汉字 / 数字 / 字母 / 单位 / 符号彼此紧贴，**只保留「拉丁字母 + 空格 + 拉丁字母」**
  （`1.5mM Cu^{2+}` 里的那个空格要留，否则连成一个词没法读）。例：`O2`、`45°C`、`2024年`。
- **化学式与单位用真角标**：`Fe^{3+}`、`I_{D}/I_{G}`、`元/m^{2}`。
  **不许**写 Unicode 上下标（`Fe³⁺`、`m²` 微软雅黑缺字形 → 豆腐块，`E1` 拦），
  **也不许**直写 `Fe3+`（`E7` 拦）。
- **禁破折号**；数值区间用 `~`（`30~45°C`）。
- **行尾不许是左括号**（断行时要把左括号连同后文挪到下一行）。

## 环境

在**仓库根**（含 `build.py` 的目录）执行。**必须用仓库内的 `.venv`** —— 系统 python 没装依赖：

```bash
.venv/Scripts/python.exe build.py <任务id> --check     # Windows
.venv/bin/python        build.py <任务id> --check     # macOS / Linux
```

装了 `make` 的话：`make check TASK=<id>` / `make test` / `make list`。

## 标准流程

```
① 备料     文案 + 配图(放 tasks/<id>/assets/) + 官方模板 pptx
② 建任务   python build.py --new <id>      # 从 tasks/_template.md 复制
③ 写文档   编辑 tasks/<id>/task.md（front-matter 设置 + ## 小节 + <!-- figure -->）
④ 构建     python build.py <id> --check
⑤ 读报告   dist/compliance-<id>.md —— 硬性项必须全绿（退出码 0）
⑥ 亲眼看   Read dist/preview_intro.png 逐块检查；必要时用 PowerPoint 导出实排图核对
⑦ 交付     present_files 给出 dist/<output>.pptx
```

**② 备料阶段最容易出的错**：只读文档正文、漏掉表格与插图里的数据。
读 `.doc` 稿件必须连**表格**和**内嵌图**一起读 —— 否则会误判"稿件里没有数据"。

**⑥ 这一步不能省**：`--check` 全绿只代表"按模型自洽"，**必须亲眼看渲染结果**再交付。
「模型自己证明自己」是本项目反复踩过的坑。想看真渲染，用 PowerPoint COM 导出：
先 `cp` 产物到临时目录（**别让渲染器直接打开产物**，会留写锁），再
`$pres.Slides.Item(1).Export($png, "PNG", 2100, 5250)`。

## task.md 速查

```markdown
---
id: my-poster
title: 某某比赛 · 某某墙报          # 只用于日志
template: "assets/template.pptx"   # 官方模板（相对本文件）
output: my-poster.pptx             # 产物名
dist: ../../dist                   # 产物目录
figures_dir: assets                # 配图目录
number: QB001                      # 可选：作品编号（写了才覆写模板编号框）
area: auto                         # auto = 由模板占位框推导；或 [x0,y0,x1,y1] cm
grid:                              # 每行放哪些小节，不重不漏
  - [0]
  - [1]
  - [2, 3]
row_fracs:                         # 可选：行内列宽比例（每行和为 1）
  - [1.0]
  - [0.6, 0.4]
style:                             # 可选：覆盖 config.OVERRIDABLE 里的键
  BODY_MAX: 4.20
---

## 小标题                          ← 一个分块，顺序即展示顺序
<!-- figure: 图.png | 图1  图注 -->   ← 本块配图，; 分隔多张，|| 分行成图网格
正文用 **两个星号** 标红；化学式写 Fe^{3+}（上标）、I_{D}/I_{G}（下标）。
```

| 指令 | 作用 |
|---|---|
| `<!-- figure: 文件 \| 图注 -->` | 配 1 张图；多张用 `;` 分隔（≤3 张，等高并排成「图条」） |
| `<!-- figure: a \| 图1 ; b \| 图2 \|\| c \| 图3 -->` | **图网格**：`\|\|` 分「图条行」，上下叠排（≤3 行）—— 分栏块里把图放大的唯一手段 |
| `<!-- figure: none -->` | 本块不配图（纯文本块） |
| `<!-- mode: auto\|stack\|side\|text -->` | 强制排法：文上图下 / 文左图右 / 只要文字 |
| `<!-- caption: 图1 甲 ; 图2 乙 -->` | 单独指定图注（条数须与图数一致） |

要点：**每段一行**（段内换行被忽略，空行才分段）；**每条指令在一个小节里只能写一次**；
**指令名写错会报错**，不会静默忽略。

## 交付前检查单

- [ ] `--check` 硬性项全绿（退出码 0）
- [ ] 亲眼看 `preview_intro.png`，逐块确认：图文对位、无压字、无溢出、标点与空格符合规范
- [ ] 正文字数没超上限；超了是删铺垫句，不是放宽阈值
- [ ] 作品编号（若用户要）已写进 `number:`
- [ ] 产物用 `present_files` 交付，并说明改动落在哪些文件

## 已知坑（会复发的）

- **PowerPoint 允许半角 `)` 落行首**，实排会断出一条短行、行末留白较大。见到别急着改求解器
  —— 与模型的 `NO_START` 不一致但**行数一致**。想消掉只能动文案。
- **渲染器会量化**：`spcPts` 被取整到整点、`sz` 抬档。要量真值用 `tools/probe_metrics.py`。
- **产物被别的程序握写锁** → 构建报 `PermissionError`。这不是内容错误。
  `writer.save` / `preview._save_png` 已改原子写（临时文件 + `os.replace` + 退避重试）；
  排查用 `[IO.File]::Open(p,'Open','ReadWrite','None')` 测锁、看 `~$` 开头锁文件。
- **`a:bodyPr` 自动调整三选一**，同时挂两个 → PowerPoint 判定文件损坏、打不开。
- **`python-pptx` 的 `gradient_angle` setter 是反的** → 直接改 `a:lin/@ang`。
- **模板带亚 0.01cm 坐标噪声** → `area: auto` 探测时先吸附到 0.01cm。
- **改引擎公开字段/语法**必须同步测试与文档；收尾三件套 = **runner 全绿 + check 全绿 + grep 无旧说法**。
- **公开仓库只发引擎**：具体任务的文案、素材、模板、成品都不入库
  （`.gitignore` 排除 `/tasks/*`、`/assets/`、`/dist/`、`/legacy/`、`/.workbuddy/`）。
  往文档或测试里写示例数字时**一律用中性占位**（`12.34 元/m²`），永不用真实作品数值。
